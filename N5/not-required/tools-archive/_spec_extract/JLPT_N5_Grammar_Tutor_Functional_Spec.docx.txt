[Heading 1] 1) Purpose & Goals
Build a PC-friendly, browser-based web app that:
[List Bullet] Teaches all JLPT N5 grammar patterns in a structured Chapter 1 format (TOC → meaning → form/connection → explanation → examples → common mistakes → simple Japanese meaning).
[List Bullet] Provides an auto-graded test (Chapter 2) attemptable on a PC.
[List Bullet] Enforces: Submit button visible-but-disabled until all questions are answered; results display immediately after Submit (no reload).
[List Bullet] Performs gap analysis using rolling-history thresholds (Chapter 3) and reteaches weak patterns with form rules, common mistakes, and fresh examples.
[List Bullet] Drives a Drill mode (Spaced Repetition) over weak patterns at 1d / 3d / 7d / 14d intervals.
[List Bullet] Summarizes mastered / weak / untested patterns and recommends next steps (Chapter 4).
[List Bullet] Runs on GitHub Pages as a static site with zero build step. Anyone with a modern browser can clone and double-click `index.html`.

[Heading 1] 4) Content Rules (Hard Requirements)
[Heading 2] 4.1 JLPT N5 Scope Constraints
[List Bullet] All lesson examples and test content must use only N5-scope vocabulary (per `KnowledgeBank/vocabulary_n5.md`) and N5-scope kanji (per `KnowledgeBank/kanji_n5.md`).
[List Bullet] If out-of-scope text is unavoidable: prefer N5 alternative; otherwise apply furigana rule (§4.2) to the specific word only.
[List Bullet] No romaji anywhere in lesson or test content. Force kana reading.
[Heading 2] 4.2 Furigana Rules (Strict)
[List Bullet] Default: furigana OFF on N5-scope kanji. This matches a late-N5 learner; the goal is reading practice, not crutches.
[List Bullet] Always furigana ON for any kanji or word beyond N5 scope, on the specific word only - never the entire sentence.
[List Bullet] Per-session toggle: "Show furigana on N5 kanji" - learner can flip ON for extra support; OFF is the default and persists in LocalStorage.
[List Bullet] Furigana rendering must be a true ruby annotation (`<ruby><rt>`), not parenthetical. Must support per-character or per-word annotation, not whole-sentence.
[Heading 2] 4.3 Lesson Template (Chapter 1) - 7 Blocks
For each grammar pattern, display in this exact order:
[List Number] Pattern name - e.g., 〜です／〜ます
[List Number] Meaning (English) - short gloss.
[List Number] Form & connection rules - what does the pattern attach to (noun / い-adj / な-adj / verb-which-form)? Include a small conjugation table where applicable (affirmative / negative / past / past-negative / question).
[List Number] Explanation & usage (English) - when to use it, register, nuance.
[List Number] Example sentences (4-6 for fundamentals; 2-3 for narrow patterns) - must follow the form-variety rule (§4.6).
[List Number] Common mistakes / contrasts - pairs like 「は vs が」, 「に vs で」, 「あります vs います」, 「上手 vs 得意」. At least one entry where applicable. Include a strikethrough wrong sentence with one-line "why this is wrong" where helpful.
[List Number] Meaning (Japanese, simple) - N5 kanji allowed, no out-of-scope words, hiragana otherwise. Provides reading reinforcement.
[Heading 2] 4.4 Canonical Pattern Source
[List Bullet] The canonical pattern coverage list is the local file `KnowledgeBank/grammar_n5.md` (in this directory) - 23 categories, exhaustive at N5 level.
[List Bullet] TOC ordering follows that file's 23-category structure: copula → particles → demonstratives → question words → verbs (ます-form, plain form) → te-form → adjectives → existence → comparison → desiderative → counters → time → conjunctions → giving/receiving → causation → nominalization → set patterns → frequency → polite phrases → other core patterns → honorifics.
[List Bullet] Every pattern listed in `KnowledgeBank/grammar_n5.md` MUST have a matching entry in `/data/grammar.json`. A coverage-check script (`tools/check_coverage.py`) enforces this - fails commit if a pattern is missing.
[List Bullet] Authoritative reference sources for content quality are documented in `KnowledgeBank/sources.md` (Genki, Minna no Nihongo, Try!, Makino & Tsutsui, Marugoto, Bunpro, etc.).
[Heading 2] 4.5 meaning_ja Rule
[List Bullet] N5 kanji ALLOWED for content nouns/verbs.
[List Bullet] All other words MUST be hiragana.
[List Bullet] No out-of-scope kanji or vocabulary.
[List Bullet] No romaji.
[List Bullet] If an out-of-scope word is unavoidable, apply furigana to that word only.
[Heading 2] 4.6 Example Variety Rule
For fundamental patterns (high frequency: は、が、を、に、〜ます、〜ました、〜てください、〜たい、etc.), provide 4-6 examples with form variety:
[List Bullet] At least 1 affirmative.
[List Bullet] At least 1 negative.
[List Bullet] At least 1 question.
[List Bullet] At least 1 past tense (where applicable).
[List Bullet] Optionally 1 mini-dialogue.
Each example MUST declare a `form` field: `affirmative` | `negative` | `question` | `past` | `dialogue`.
For narrow patterns (e.g., specific particles like 「や」), 2-3 examples are acceptable.
[Heading 2] 4.7 N5 Vocabulary Whitelist
[List Bullet] `KnowledgeBank/vocabulary_n5.md` is the canonical N5 vocabulary scope list.
[List Bullet] Generated artifact `/data/n5_vocab_whitelist.json` is consumed by the content lint script.
[List Bullet] Lint script flags any token in `/data/grammar.json` and `/data/questions.json` that is not on the whitelist (excluding hiragana-only function words / particles / explicit furigana-tagged out-of-scope words).
[Heading 2] 4.8 N5 Kanji Whitelist
[List Bullet] `KnowledgeBank/kanji_n5.md` is the canonical N5 kanji scope list.
[List Bullet] Generated artifact `/data/n5_kanji_whitelist.json` is consumed by the furigana renderer and the lint script.
[List Bullet] The furigana renderer treats any kanji NOT on this whitelist as out-of-scope and renders furigana for it; kanji ON this whitelist render furigana only when the user toggle is ON.
[Heading 1] 5) UX / UI Requirements
[Heading 2] 5.1 Global Navigation
Primary navigation tabs (in this order):
[List Bullet] Learn (Chapter 1)
[List Bullet] Test (Chapter 2)
[List Bullet] Drill (NEW - SRS-driven mini-sessions on weak patterns; shows count badge of items due today)
[List Bullet] Review Weak Areas (Chapter 3)
[List Bullet] Summary (Chapter 4)
[Heading 2] 5.2 Chapter 1 - Learn
[List Bullet] TOC page lists all N5 grammar patterns grouped by category (per `KnowledgeBank/grammar_n5.md`'s 23 categories).
[List Bullet] Each TOC entry shows pattern name + a small "known / weak / untested" badge derived from rolling history.
[List Bullet] Clicking a pattern opens the 7-block detail view (§4.3).
[List Bullet] Provide Next / Previous pattern navigation within and across categories.
[List Bullet] Provide search/filter by keyword (pattern name, meaning, or category).
[List Bullet] Provide a "Mark as known" checkbox per pattern (manual override; updates rolling history).
[Heading 2] 5.3 Chapter 2 - Test
[Heading 3] Test Setup
[List Bullet] Default test length: 20 questions. Selectable: 20 / 30 / 50.
[List Bullet] First-time learner: a one-time prompt offers the Diagnostic Test (§5.7) before the first real test.
[List Bullet] Question types (auto-gradable):
[List Bullet]   Multiple choice (single correct).
[List Bullet]   Fill-in-blank with dropdown (preferred for particles).
[List Bullet]   Sentence ordering (並べ替え) - 4-5 word/phrase tiles, click to order.
[List Bullet]   Optional: strict short input (exact match with normalization rules).
[List Bullet] Question sampling MUST balance across categories (no single-category dominance), unless test length < 8.
[Heading 3] Attempting
[List Bullet] Progress indicator: "Question X of N" + a thin progress bar.
[List Bullet] Allow Next / Previous navigation.
[List Bullet] Optional "Flag question" feature (icon toggle; flagged items grouped at end of review).
[Heading 3] Submit Button Rule (Mandatory)
[List Bullet] Submit button is always visible on the last question.
[List Bullet] Until every question has an answer, Submit is disabled and shows a tooltip on hover: "Answer all questions to submit" plus a remaining-count: "3 questions still unanswered".
[List Bullet] Once all questions are answered, Submit becomes enabled (no extra confirmation step).
[List Bullet] This rule is non-negotiable across all question types and test lengths.
[Heading 3] Post-Submit Behavior (Mandatory)
[List Bullet] Clicking Submit triggers immediate in-place results rendering.
[List Bullet] No manual grading.
[List Bullet] No page reload.
[List Bullet] Test responses are appended to rolling history in LocalStorage before the results screen renders.
[Heading 2] 5.4 Results Screen (After Submit)
Three sections, in this order:
[Heading 3] (a) Score Summary
[List Bullet] Total score, e.g., 17/20.
[List Bullet] Correct count / incorrect count.
[List Bullet] Percentage.
[List Bullet] Time taken (optional).
[Heading 3] (b) Answer Review (per question)
[List Bullet] Question text.
[List Bullet] Learner's answer (highlighted; red if incorrect, green if correct).
[List Bullet] Correct answer (clearly shown).
[List Bullet] Explanation of why the correct answer is correct.
[List Bullet] Per-distractor explanation for high-confusion questions: only the distractor the learner picked is explained (not all four), to avoid cognitive overload.
[List Bullet] Tagged grammar pattern(s) with link to Chapter 1 detail page.
[Heading 3] (c) Grammar Gap List
[List Bullet] Patterns flagged as weak by rolling-history threshold (§6.6): `errors/attempts ≥ 0.5 AND attempts ≥ 2`.
[List Bullet] Each item links to Chapter 3 (Review Weak Areas).
[List Bullet] Each weak pattern is auto-queued into Drill at the 1-day interval.
[Heading 2] 5.5 Chapter 3 - Review Weak Areas
For each weak grammar pattern, display:
[List Bullet] Pattern name.
[List Bullet] Meaning + explanation (English).
[List Bullet] Form & connection rules + common mistakes (re-shown with extra emphasis).
[List Bullet] Why the wrong answer was wrong (per-distractor explanations pulled from missed questions).
[List Bullet] New examples (4-6 if fundamental, 2-3 otherwise) - must be DIFFERENT from Chapter 1 examples to avoid memorization-by-position.
[List Bullet] "Drill these now" button → opens an SRS Drill session focused on this pattern.
[Heading 2] 5.6 Chapter 4 - Summary
[List Bullet] Mastered patterns - seen ≥ 2 times AND error rate < 30% over rolling history (or manually marked known).
[List Bullet] Patterns needing more practice - `errors/attempts ≥ 0.5 AND attempts ≥ 2`.
[List Bullet] Untested patterns - seen 0-1 times → "Take a test to assess."
[List Bullet] Suggested next steps: Drill due items / Re-attempt test on weak patterns / Take Diagnostic if not yet done.
[List Bullet] Visual: a heatmap-style grid by category showing strength (green) / weak (red) / untested (gray).
[Heading 2] 5.7 NEW: Diagnostic Test (First Run)
[List Bullet] Prompt on first visit (and re-runnable from Settings): "Take a 10-question diagnostic to map your current strengths?"
[List Bullet] 10 questions, sampled across the 23 categories of `KnowledgeBank/grammar_n5.md` with priority on the highest-frequency categories (copula, particles, verbs, adjectives, te-form, tai-form, counters, conjunctions, demonstratives, question words).
[List Bullet] Results don't count toward score history but DO seed the initial weak-pattern list and Drill queue.
[List Bullet] Skippable - learner can go straight to lessons or full test.
[Heading 2] 5.8 NEW: Drill Mode (SRS-light)
[List Bullet] Driven by LocalStorage: per-pattern SRS state.
[List Bullet] Intervals: 1 day / 3 days / 7 days / 14 days (Leitner-style boxes).
[List Bullet] A pattern enters Drill on:
[List Bullet]   First miss in a Test or Diagnostic.
[List Bullet]   Any wrong answer in a previous Drill session.
[List Bullet] A pattern advances to the next interval on a correct answer; resets to 1d on wrong.
[List Bullet] A pattern graduates (leaves Drill) after 4 consecutive correct answers across boxes.
[List Bullet] UI: "Drill" tab shows a count badge of patterns due today.
[List Bullet] A Drill session = 5-10 questions sampled from due patterns. Feedback is immediate per question (not batched like the full Test).
[List Bullet] Drill respects the visible-but-disabled Submit rule for any multi-question Drill batch ≥ 5 questions.
[Heading 1] 6) Functional Requirements (Detailed)
[Heading 2] 6.1 Grammar Content Management
[List Bullet] FR-L1: System shall load `/data/grammar.json` at startup.
[List Bullet] FR-L2: System shall render TOC grouped by category (per `KnowledgeBank/grammar_n5.md`'s 23 categories), in declared order.
[List Bullet] FR-L3: System shall render pattern detail using the 7-block expanded template (§4.3).
[List Bullet] FR-L4: System shall support cross-linking from Test results → Chapter 1 pattern detail and Chapter 3 review.
[List Bullet] FR-L5: System shall enforce that every pattern in `KnowledgeBank/grammar_n5.md` has a matching entry in `/data/grammar.json`. The `tools/check_coverage.py` script verifies this and exits non-zero if any pattern is missing.
[Heading 2] 6.2 Test Engine
[List Bullet] FR-T1: Generate tests from `/data/questions.json`. Each question requires: `id`, `grammarPatternId`, `type`, `correctAnswer`, `choices` (for MCQ/dropdown) OR `tiles`+`correctOrder` (for sentence_order). Recommended: `explanation_en`, `distractor_explanations`.
[List Bullet] FR-T2: Enforce "all answered before Submit becomes enabled" via visible-but-disabled rule (§5.3).
[List Bullet] FR-T3: Compute score instantly on Submit.
[List Bullet] FR-T4: Display results immediately after Submit (no reload).
[List Bullet] FR-T5: Produce gap list using rolling threshold (§6.6), not single-test snapshot.
[List Bullet] FR-T6: Support `sentence_order` question type with array-equality grading.
[List Bullet] FR-T7: Sample test questions to balance across categories - no single category may exceed `ceil(N / 5)` questions in a test of length N (where N ≥ 8).
[Heading 2] 6.3 Answer Normalization (if short input is used)
[List Bullet] FR-N1: Trim whitespace; convert full-width ↔ half-width as appropriate.
[List Bullet] FR-N2: Support multiple acceptable answers (array) where defined.
[List Bullet] FR-N3: Normalize hiragana / katakana variants where the question allows either.
[Heading 2] 6.4 Progress & Persistence (REQUIRED)
[List Bullet] FR-P1: Persist test results, weak patterns, SRS state, and rolling pattern history in LocalStorage.
[List Bullet] FR-P2: Provide a "Reset progress" button with a two-step confirmation.
[List Bullet] FR-P3: Persist learner's furigana toggle preference and last-selected test length.
[List Bullet] FR-P4: Use the LocalStorage key namespace `jlpt-n5-tutor:*` to avoid collisions.
[Heading 2] 6.5 NEW: Per-Distractor Explanations
[List Bullet] FR-D1: For questions with `high_confusion: true`, every distractor MUST have an explanation in `distractor_explanations`.
[List Bullet] FR-D2: Results screen shows the distractor explanation only for the choice the learner picked, not all distractors - to avoid information overload.
[List Bullet] FR-D3: Chapter 3 (Review Weak Areas) aggregates distractor explanations from all missed questions for the same pattern.
[Heading 2] 6.6 NEW: Weak Pattern Detection (Threshold-Based)
[List Bullet] FR-W1: A pattern is "weak" if `errors / attempts ≥ 0.5` AND `attempts ≥ 2` over rolling history (not single-test).
[List Bullet] FR-W2: Single-test results contribute to rolling history; rolling history is preserved across sessions in LocalStorage.
[List Bullet] FR-W3: A pattern graduates from "weak" to "mastered" after 4 consecutive correct answers across Drill or Test.
[List Bullet] FR-W4: Manual override: learner can mark a pattern "known" from Chapter 1, which sets it to mastered until the next miss.
[Heading 2] 6.7 NEW: SRS State Management
[List Bullet] FR-S1: Track per-pattern SRS box: `1d` / `3d` / `7d` / `14d` / `graduated`.
[List Bullet] FR-S2: Surface patterns in Drill where `nextDue ≤ now`.
[List Bullet] FR-S3: Do NOT preemptively drill patterns with no missed history.
[List Bullet] FR-S4: Wrong answer in Drill resets the pattern to box `1d` and `consecutiveCorrect = 0`.

[List Bullet] Zero install for the learner - just a browser.
[List Bullet] Zero install for the content author - edit JSON / MD in any editor; refresh browser.
[List Bullet] Stable across Chrome / Edge / Firefox versions; no breaking-change surface from build tools.
[List Bullet] GitHub Pages compatible without any actions or workflows.
[List Bullet] No external CDN dependencies - everything is in the repo (resilient on flaky networks).
[Heading 2] 8.3 Content Pipeline (One-Time per Edit)
[List Bullet] Source-of-truth files: `KnowledgeBank/grammar_n5.md`, `KnowledgeBank/kanji_n5.md`, `KnowledgeBank/vocabulary_n5.md`, `KnowledgeBank/sources.md` (human-readable).
[List Bullet] App-consumed files: `/data/grammar.json`, `/data/questions.json`, `/data/n5_kanji_whitelist.json`, `/data/n5_vocab_whitelist.json`.
[List Bullet] `tools/build_data.py` - one-time conversion script (run by author after editing .md files). Generates JSON whitelists from kanji_n5.md and vocabulary_n5.md.
[List Bullet] `tools/check_coverage.py` - verifies every pattern in grammar_n5.md has an entry in grammar.json.
[List Bullet] `tools/lint_content.py` - flags non-N5 vocabulary or kanji in grammar.json / questions.json.
[List Bullet] These scripts are author-side only. The learner never runs Python.

[Heading 3] B.15 Microinteractions vs Zen Modern — formal spec deviation (2026-05-01)
The original UI design brief (feedback/jlpt-n5-ui-design-brief.md §8.2) called for the following microinteractions:
[List Bullet] Card hover lift (translateY -2px on hover)
[List Bullet] Button press scale (transform: scale(0.98) on :active)

The v1.8.0 Zen Modern design overhaul (specifications/jlpt-n5-design-system-zen-modern.md §0.5 + §8) explicitly forbids these:
> §0.5: "No shadows, no gradients, no glass effects. Ever. Including hover states."
>
> §8: Forbidden motion: bouncy springs, confetti, card lift / shadow on hover, wiggle, shake, pulse, glow, sliding panes, fading in entire pages from blank.
Resolution (this section is the formal record): the Zen Modern spec supersedes the UI design brief on microinteractions. Hover affordances are rendered through:
[List Number] Background lightening (surface → surface-alt)
[List Number] Border-color strengthening (line → line-strong)
[List Number] Underline on .card-action text only
Correctness feedback in drill / test surfaces uses color + class change only — .choice-button.correct-choice gets color: var(--color-correct) + tinted background; .choice-button.wrong-choice gets the incorrect tint + strikethrough. No motion, no shake.
The Pass-15 design-system static checker (tools/check_design_system.py) enforces this:
[List Bullet] D-3 No box-shadow: declarations (other than none)
[List Bullet] D-4 No transform: inside :hover blocks
[List Bullet] D-8 No decorative text-shadow
Any future re-introduction of the UI design brief's microinteractions would fail D-3, D-4, or D-8 in CI. This guards the Zen Modern aesthetic against drift back to the SaaS-default microinteraction palette.

[Heading 3] F.1 Mobile UI contract — new NFR cluster (NFR-M1..NFR-M9)
The mobile experience hardening pass shipped a desktop-safe contract that gates every mobile-specific style behind explicit breakpoints and verifies desktop is byte-identical after each sweep. The contract is normative for any future mobile work in this codebase.
Breakpoint tier:

Non-functional requirements:
[List Bullet] NFR-M1 Tap-target floor — every interactive element ≥ 44 px on its smallest dimension. Auxiliary controls (icon-btn, breadcrumb back-link, footer-nav links, pattern-nav arrows, known-toggle) carry mobile-only min-height: 44px rules so the global floor reaches them.
[List Bullet] NFR-M2 iOS auto-zoom prevention — every text/search/email/number input + textarea + select rendered at ≥ 16 px on ≤768 breakpoint. Required because iOS Safari auto-zooms on tap when the input's computed font-size is below 16 px, pushing the input above the keyboard fold.
[List Bullet] NFR-M3 Overflow safety belt — html, body { overflow-x: hidden; } at ≤768 so any descendant wider than viewport never triggers page-wide horizontal scroll on a 320 px phone. Defensive; current state has zero overflow at 320 px.
[List Bullet] NFR-M4 Body type-floor — body { font-size: max(16px, var(--text-base)); } at ≤768. Respects the user's font-size knob (Settings > Font: S/M/L/XL); on default S/M (where --text-base resolves to 13–15 px), this lifts body to 16 px for readability and reinforces NFR-M2 by making body text ineligible for the iOS-zoom threshold trigger.
[List Bullet] NFR-M5 Visible tap feedback — every primary tap target gets a brief :active { transform: scale(0.97); opacity: 0.85; transition: 80ms } at ≤768. Mobile has no :hover equivalent; without this, tap-down feels unresponsive on slow networks.
[List Bullet] NFR-M6 Smooth scroll — html { scroll-behavior: smooth; } at ≤768. Anchor jumps + route changes animate; matches OS-level scroll snap.
[List Bullet] NFR-M7 Container gutter — at ≤480 breakpoint, main + .app-footer + .app-header collapse inline padding from desktop's 22.5 px to 16 px so cards use ~92 % of viewport width. Don't apply universal * { max-width: 100% } — it constrains SVG icons + brand-mark pseudo-elements.
[List Bullet] NFR-M8 Heading hierarchy on narrow screens — h2 clamps at 18 px (not desktop's 22 px) at ≤768. On 320 px viewports, 22 px h2 reads as indistinguishable from h1 (also 22 px) and the typographic cascade collapses. 22 / 18 / 16 (h1 / h2 / body) restores readable hierarchy.
[List Bullet] NFR-M9 Desktop safety — every mobile sweep ships with a 1280 px regression check. Every value listed above MUST match the desktop default after the sweep (body overflow-x: visible, scroll-behavior: auto, body font: ~14.06 px, main padding: 22.5 px, no :active rule applied, h2 at 22 px). The mobile rules MUST cut off cleanly at 769 px.

[Heading 1] JLPT N5 Tutor - Design System: Zen Modern (Muji)
Theme: Zen Modern - Muji-inspired
Goal: Spare, generous, almost monochrome. The product earns trust by getting out of the way. Looks credible on first load. Still looks credible in three years.
Influences: Muji catalog typography, Kinokuniya book design, Apple Human Interface circa 2014-16 (pre-glassmorphism), Japanese editorial print.
This document is the source of truth. Every page, component, and interaction in the JLPT N5 Tutor must conform to these tokens and rules. Ambiguity is resolved in favor of *less* visual weight, never more.

[Heading 2] 0. Design principles (read these before writing code)
[List Number] Hierarchy through scale and weight, not color. Color is for state (correct, wrong, due). Hierarchy comes from type size and whitespace.
[List Number] One accent color, used sparingly. The brand green is reserved for the active nav indicator, the primary CTA, and the focus ring. Nowhere else.
[List Number] Whitespace is the design. When in doubt, add 24px of vertical space, not a divider.
[List Number] Hairlines, not borders. All borders are 0.5px or 1px in a near-paper gray. Never thicker.
[List Number] No shadows, no gradients, no glass effects. Ever. Including hover states.
[List Number] No emojis, no decorative icons in body text. Use small SVG glyphs only where functional (audio play, stroke order, search).
[List Number] Typography weight 300 and 400 only for body. 500 for headings. Never 600 or 700. Heavy weights look loud against this neutral surface.
[List Number] All text is sentence case. Never Title Case. Never ALL CAPS except for tiny letter-spaced labels (e.g., "REFERENCE" above a card group).
[List Number] Numerals are tabular (`font-variant-numeric: tabular-nums`). Stats, counters, timers, and SRS intervals must align vertically.
[List Number] Japanese text uses Noto Sans JP weight 400. Mixing weights between latin and ja text creates uneven visual rhythm.
[List Number] Describe the contents. Offer no opinion about them. Homepage copy is neutral and inventorial. No outcome claims, no second-person, no verbs of encouragement, no trust reassurance, no superlatives, no quantifier softeners. Counts are bare numerals plus nouns. The product is a study material; the copy says what it is, not what it does for the visitor.
If a proposed change would violate any of these, the proposed change is wrong.

[Heading 3] 1.3 Color usage rules
[List Bullet] Primary text: always --color-text. Never near-black #000.
[List Bullet] Body backgrounds: always --color-bg. Cards step up to --color-surface.
[List Bullet] Hover backgrounds: step from --color-surface to --color-surface-alt. Never use the accent tint as a hover.
[List Bullet] Accent green: ONLY on (1) the active nav underline, (2) the primary CTA filled button, (3) focus rings, (4) progress-bar fills, and (5) the small accent line under the wordmark. Five places total. Audit your CSS to enforce this.
[List Bullet] Tinted pills (accent-tint, due-tint, etc.): use sparingly. Reserve for state badges and small status indicators. Never as backgrounds for cards or sections.
[List Bullet] Never use red or warning colors for anything except actual errors. A "review due" indicator is amber, not red.

  --weight-base:   400;
  --weight-medium: 500;

[List Bullet] Body paragraphs: --weight-base
[List Bullet] Headings (h1, h2, h3): --weight-medium
[List Bullet] Page titles only: occasional use of --weight-light for the largest hero headline (--text-2xl, weight 300) - this is the Muji signature look.
[List Bullet] Japanese text: always --weight-base. Never light, never medium. Japanese forms have built-in optical weight that doesn't need typographic emphasis.
[List Bullet] Buttons: --weight-medium.
[List Bullet] Numerals in stats: --weight-medium with font-variant-numeric: tabular-nums.
[List Bullet] Never use weight 600 or 700. They look loud against this neutral surface.

[Heading 3] 5.1.1 Copy register (mandatory)
The homepage is the most-seen surface in the app. Its copy sets the register for everything else. The rules:
[List Number] Describe the contents. Offer no opinion about them.
[List Number] No outcome claims. The product is a study material, not a promise.
[List Number] No second-person ("you", "your"). Use noun phrases or impersonal sentences.
[List Number] No verbs of encouragement ("start", "begin", "explore", "discover").
[List Number] No trust reassurance ("works offline", "no login", "privacy-first") on the homepage. Those properties live in About / Privacy.
[List Number] No service-encounter politeness ("please", "feel free to").
[List Number] Counts are bare numerals plus nouns. No "~1000", no "1000+", no "carefully selected", no "all".
[List Number] No superlatives: best, most comprehensive, complete, definitive.
[List Number] No flattering self-description: clean, minimal, elegant, distraction-free. The design demonstrates these; the copy must not assert them.
[List Number] Sentence case throughout. ALL CAPS only for the small letter-spaced section labels.
If a proposed homepage string violates any of these, the string is wrong.
The same register applies to all homepage variants: light mode, dark mode, mobile, returning-user, and translated locales.

[Heading 2] 7. Iconography
Use a small, consistent SVG icon set. Recommendation: lucide-icons subset (search, settings, play, pause, chevron-right, x, check, alert-circle, refresh-cw). Stroke width 1.5px to match the hairline aesthetic; the default 2px lucide stroke is too heavy.
svg.icon {
  width: 16px; height: 16px;
  stroke-width: 1.5;
  color: currentColor;
}
svg.icon-sm { width: 14px; height: 14px; }
svg.icon-lg { width: 20px; height: 20px; }

No icon should be larger than 24px in any UI surface except the kanji-tile glyph (which isn't an icon, it's content).
NO emojis. NO decorative icons in body text. NO colored icons.

[Heading 2] 8. Motion
Movement is minimal and purposeful.
:root {
  --motion-fast:   120ms;
  --motion-base:   180ms;
  --motion-slow:   300ms;
  --easing:        cubic-bezier(0.2, 0, 0, 1);   /* iOS-like ease-out */
}
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}

Allowed motion:
[List Bullet] Hover state transitions: --motion-fast ease-out on background and border
[List Bullet] Button press: scale to 0.98 for --motion-fast
[List Bullet] Progress bar fill: --motion-slow width transition
[List Bullet] Page transitions: cross-fade only, --motion-base. No slide, no zoom.
Forbidden motion:
[List Bullet] Bouncy springs
[List Bullet] Confetti
[List Bullet] Card lift / shadow on hover
[List Bullet] Wiggle, shake, pulse, glow
[List Bullet] Sliding panes
[List Bullet] Fading in entire pages from blank

[Heading 2] 9. Imagery and ornament
The Muji approach uses almost no imagery. What it permits:
[List Bullet] A single Japanese character as a brand mark or watermark (very low opacity). Used once on the home hero, optionally.
[List Bullet] The kanji glyphs in the Kanji index are the only "imagery" most pages need.
[List Bullet] Stroke-order diagrams in kanji detail pages: SVG, single-stroke, animated only on user click.
Forbidden:
[List Bullet] Photos of any kind (people studying, Tokyo skylines, sushi).
[List Bullet] Stock illustrations.
[List Bullet] Decorative patterns or textures.
[List Bullet] Backgrounds with visible color (everything is --color-bg or --color-surface).
[List Bullet] Brand mascot.
[List Bullet] Cherry blossoms. Especially cherry blossoms.
The product is the type, the spacing, and the hairlines. Adding decoration weakens the design.

[Heading 2] 11. Accessibility
Non-negotiable. WCAG 2.1 AA.
[List Bullet] Color contrast: minimum 4.5:1 for body text against background. The token combinations above are pre-verified.
[List Bullet] Focus rings: every interactive element has a visible focus ring (2px accent color, 2px offset).
[List Bullet] Keyboard navigation: tab order matches visual order. Esc closes modals. Arrow keys cycle drill choices.
[List Bullet] Screen readers: every Japanese text container has lang="ja". Furigana via <ruby> works correctly with VoiceOver/NVDA.
[List Bullet] Motion: all animations respect prefers-reduced-motion.
[List Bullet] Form labels: every input has an associated <label>.
[List Bullet] Headings: one <h1> per page; nested headings don't skip levels.

[Heading 2] 13. What this design is and is not
It is:
[List Bullet] Quiet, slow, considered.
[List Bullet] Built to look right after 100 hours of use, not in the App Store screenshot.
[List Bullet] Heavily reliant on disciplined typography and whitespace.
[List Bullet] A reflection of a real Japanese aesthetic tradition (Muji, MoMA, Kinokuniya).
It is not:
[List Bullet] Friendly, warm, gamified, or "fun."
[List Bullet] Designed for users who want streaks, badges, XP, or push notifications.
[List Bullet] Forgiving of half-hearted execution. A 70% implementation will look worse than the current bland design. Either commit fully or pick a more forgiving theme.
If you can't ship it at 95% fidelity to this spec, ship something more forgiving. This design works because of its discipline. Halfway is worse than starting over.

[__TABLE__] [table 5 start: 26 rows x 2 cols]
[TableRow] Term | Definition
[TableRow] JLPT | Japanese Language Proficiency Test (Japan Foundation / JEES). Five levels: N5 (easiest) to N1.
[TableRow] N5 | Lowest JLPT level. ~80-100 kanji, ~600-800 vocab, ~80-100 grammar patterns (no canonical post-2010 list).
[TableRow] Moji (文字) | "Characters." JLPT subsection testing kanji recognition / orthography.
[TableRow] Goi (語彙) | "Vocabulary." JLPT subsection testing word meaning and paraphrase.
[TableRow] Bunpou (文法) | "Grammar." JLPT subsection testing particle usage and sentence form.
[TableRow] Dokkai (読解) | "Reading comprehension." JLPT subsection.
[TableRow] Choukai (聴解) | "Listening comprehension." JLPT subsection.
[TableRow] Furigana | Small kana written above kanji indicating reading. Rendered as <ruby><rt> in HTML.
[TableRow] Kun-yomi | Native Japanese reading of a kanji (e.g., 山 = やま).
[TableRow] On-yomi | Sino-Japanese (imported) reading of a kanji (e.g., 山 = サン in compounds).
[TableRow] Bika-go (美化語) | "Beautifying language" - the polite お/ご prefix on common nouns (お茶, お金). NOT honorifics (sonkei-go).
[TableRow] Sonkei-go (尊敬語) | True honorific language (いらっしゃる, おっしゃる). Out of N5 scope.
[TableRow] Te-form (て形) | Verb conjugation used for sequencing, requests, and many compound forms.
[TableRow] Tara-form / Tari-form | Conditional / non-exhaustive listing forms.
[TableRow] SRS | Spaced Repetition System. Algorithm-driven review scheduling.
[TableRow] SM-2 | SuperMemo-2 algorithm (Wozniak). Adjusts interval based on a 4-button grade (Again/Hard/Good/Easy) and an "ease factor."
[TableRow] Leitner | Earlier SRS approach using fixed-interval boxes (1d / 3d / 7d / 14d). v3 spec referenced this; the app now uses SM-2.
[TableRow] PWA | Progressive Web App. Installable, offline-capable web application backed by a service worker + manifest.
[TableRow] Service worker (SW) | Browser-side script that intercepts fetches, caches assets, and enables offline. Current version: jlpt-n5-tutor-v24.
[TableRow] Stale-while-revalidate | Caching strategy: serve cached content immediately; refetch in background; update on next request.
[TableRow] WCAG 2.1 AA | Web Content Accessibility Guidelines, level AA. The conformance target for this app.
[TableRow] Pass-N audit | The project's content-review protocol. Each pass applies a chosen audit lens (paper-maker, native-teacher, external 日本語教師, etc.). 10 passes have run; 462 findings; 0 open. Documented in verification.md.
[TableRow] KB | KnowledgeBank - the KnowledgeBank/ directory holding the source-of-truth catalog files (grammar, vocabulary, kanji, sources).
[TableRow] CP932 | Microsoft's superset of Shift-JIS used by Windows JP terminals. The codebase is em-dash-free for cp932 console safety.
[TableRow] gTTS | Google Text-to-Speech (Python library). Used at build time only to render the 491 MP3 audio files.
